# Shared browser views and admin log stream

Browser pages use `shared.page_views.render_page`: direct GETs and history restores render `base.jinja2`; HX-Request GETs return a single `#content-container` fragment, swapped with `outerHTML`. Home, login, user/profile, BIM library/editor/viewer and passport calculation/report/comparison share that boundary. Navigation and long-running calculation/upload/conversion forms use explicit HTMX requests; binary/CSV/JSON downloads remain native. The viewer header Back link explicitly uses the same swap. Bolt autodiscovers the mycelium API; it must not also be mounted into config.api. See [Loading and task feedback](LOADING_AND_TASK_FEEDBACK.md) for the pending-request lifecycle.

Authorized staff open **Live logs** from the shared header. The viewer appears in a native popover and keeps the current model, map or form visible. Close, Escape or an outside click dismiss it. The dialog has a labelled heading, initial focus on Close and keyboard-accessible output. Its connecting/reconnecting state has readable status text and a reduced-motion spinner. `/admin/logs/` remains an authorized entry page with a button to open the same popover.

The popover streams structured logs using native Bolt `/ws/logs` (without a trailing slash). This is a session-authenticated browser feature. Staff status and the dedicated `shared.view_application_logs` permission are required for both the controls and the stream. Active superusers already have that permission; grant it explicitly to other staff users or their groups in Django Admin. Anonymous HTTP requests redirect to the existing login; insufficient privilege returns 403. The socket rejects unauthorized or foreign-Origin clients before accept and rechecks session and privileges during playback. Revocation closes with 4403. The old global Channels consumer now enforces the same permission.

Django-bolt's [session authentication](https://bolt.farhana.li/topics/authentication/#using-django-decorators) documents Django permission decorators with `django_middleware=True`. Its [permissions guide](https://bolt.farhana.li/topics/permissions/#when-to-use-a-dependency-instead) distinguishes native token-claim guards from database-backed runtime checks. Existing session logins use the latter; no tokens are placed in URLs or minted from browser input.

`SharedLogHandler` records Python INFO+ application logs in a separate SQLite journal at `data/live-logs.sqlite3`, overridable with ADMIN_LOG_PATH. This is independent of user uploads and report storage. Up to 2,000 entries remain (8,000 characters each); clients load the latest 200 then stream new entries in bounded batches. SQLite coordinates application processes, so no Redis is needed for this stream. Rust-only stdout/stderr and external services are not captured by Python logging. Workers need a shared writable journal path in a multi-host deployment. Storage failures cannot fail business requests.

The browser retains at most 1,000 displayed entries, renders text safely, and supports pause/resume, clear and follow mode. It opens a connection only while the popover is open, reconnects after transient disconnections during that time, and cancels the retry and closes the socket on dismissal, page exit or HTMX cleanup. Reopening loads a fresh recent window; old socket callbacks cannot repopulate a closed or reopened viewer. Permission denial stops reconnection. HTTP responses are no-store; log entries are held in the current popover session and are absent from page fragments and history snapshots.

Initial stream verification covered full/fragment/history rendering, unchanged source conversion, CSRF and ownership, log retention/cursor reads, native socket streaming, anonymous/nonstaff denial, foreign-Origin rejection and live permission revocation. Popover tests additionally cover closed-state inactivity, connection on opening, close/reopen isolation, retry cancellation, literal text, bounded display, pause/follow controls and cleanup. Permission-aware rendering checks retain one persistent log popover in the full shell and no duplicate viewer in content fragments.

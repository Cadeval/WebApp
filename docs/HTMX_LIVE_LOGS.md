# Shared browser views and admin log stream

Browser pages use `apps.shared.page_views.render_page`: direct GETs and history restores render `base.jinja2`; HX-Request GETs return a single `#content-container` fragment, swapped with `outerHTML`. Home, login, user/profile, BIM library/editor/viewer and passport calculation/report/comparison share that boundary. Navigation uses HTMX; binary/CSV/JSON downloads and existing POST forms opt out of inherited boosting. The viewer header Back link explicitly uses the same swap. Bolt autodiscovers the mycelium API; it must not also be mounted into config.api.

`/admin/logs/` streams structured logs using native Bolt `/ws/logs` (without a trailing slash). This is a session-authenticated browser feature. Staff status and the dedicated `shared.view_application_logs` permission are required. Active superusers already have that permission; grant it explicitly to other staff users or their groups in Django Admin. Anonymous HTTP requests redirect to the existing login; insufficient privilege returns 403. The socket rejects unauthorized or foreign-Origin clients before accept and rechecks session and privileges during playback. Revocation closes with 4403. The old global Channels consumer now enforces the same permission.

Django-bolt's [session authentication](https://bolt.farhana.li/topics/authentication/#using-django-decorators) documents Django permission decorators with `django_middleware=True`. Its [permissions guide](https://bolt.farhana.li/topics/permissions/#when-to-use-a-dependency-instead) distinguishes native token-claim guards from database-backed runtime checks. Existing session logins use the latter; no tokens are placed in URLs or minted from browser input.

`SharedLogHandler` records Python INFO+ application logs in a separate SQLite journal at `data/live-logs.sqlite3`, overridable with ADMIN_LOG_PATH. This is independent of user uploads and report storage. Up to 2,000 entries remain (8,000 characters each); clients load the latest 200 then stream new entries in bounded batches. SQLite coordinates application processes, so no Redis is needed for this stream. Rust-only stdout/stderr and external services are not captured by Python logging. Workers need a shared writable journal path in a multi-host deployment. Storage failures cannot fail business requests.

The browser retains at most 1,000 displayed entries, renders text safely, supports pause/resume, clear and follow mode, reconnects after transient disconnections, and closes its socket during HTMX cleanup. HTTP responses are no-store and HTMX history caching is disabled on the log page.

After final cleanup changes, 18 affected Python tests passed again.
